## Findings and corrections

1. **Actual application bug fixed:** workflow simulation with `CURRENT_ASSIGNEE` returned no responsible users for assigned ordinary documents. The simulator incorrectly read `doc.assign`; ordinary documents store `doc.assignee`. `server.js` now resolves that ID against active users. A regression test reproduced the failure before the fix and passed afterward. It also verifies that genuinely unassigned documents still produce an empty candidate list and a warning.
2. **Obsolete Special Report expectations corrected:** eight API failures came from tests expecting the retired `/complete` endpoint, assignment completion behavior, and old audit wording. The updated tests verify submission, compliance, supervisor/division/department review, clearance, log-out, closed assignments, and workflow audit events. They explicitly verify that direct completion remains blocked.
3. **Obsolete browser navigation corrected:** Special Reports configuration now lives within Reference lists, generated reports appear in the dashboard registry, and Leave Types requires selecting its reference tab. Browser tests now use those current screens.
4. **Added a repeatable isolated runner:** `test/run-regression.js` creates a fresh demo database per suite, records test/server logs and JSON results, adapts old Linux screenshot paths in temporary test copies, and uses Edge on Windows. Added `test/document.ui.test.js` and `test/seed-qa-demo.js`.

No other functional failures or browser JavaScript exceptions were found in the completed scenarios. This is functional regression testing, not a production load test or a comprehensive security audit.

## Repeat the tests

From this application directory, run:

```powershell
node test/run-regression.js
```

With Playwright available to Node, run the browser suites:

```powershell
node test/run-regression.js workflow.ui phase11.ui schedule.ui schedule.attack.ui splash document.ui
```

If Playwright is installed outside the project, set `NODE_PATH` to its package directory. Each run writes timestamped artifacts under `.test-runs`; server logs and databases are retained for investigation. The isolated runner shuts down its suite servers. The interactive demo was separately left running with the simulation fix loaded.

Restart the interactive demo when needed:

```powershell
$env:HOST='127.0.0.1'
$env:PORT='3130'
$env:DATA_DIR='.test-runs/interactive-demo-20261007'
$env:SEED_DEMO='1'
$env:TZ='Asia/Manila'
node server.js
```

Run the seeder only against a fresh isolated demo: it intentionally adds records and is not idempotent.
